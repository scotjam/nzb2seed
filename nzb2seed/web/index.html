Build a torrent from Usenet

  1. Search for a release or a season, or upload a .torrent file you already have.
  2. Pick the torrent on the left; the matching NZBs on the right are ticked for you.
  3. SABnzbd downloads the best-matching post: +Repair when the torrent holds RARs, +Repair/Unpack when it holds unpacked files, never +Delete.
  4. The files are arranged exactly like the torrent: Sample, Proof and Subs folders, text files only fixed when that makes their pieces verify, everything else removed.
  5. qBittorrent gets the torrent stopped, pointed at the files, and rechecked.
  6. You end with 100.0% and nothing downloaded over BitTorrent.

        Automatic builds
        
        
        autobrr drops torrents from the filters you pick into a folder; nzb2seed builds each one from Usenet by itself - it waits for the post, never asks, never downloads over BitTorrent, and starts seeding only at a 100.0% recheck.
        
      
        
      
    
        
    
        
    
        
      
        
        
        autobrr
        
        
        
          
          
        
        
        
        
          
          
        
        
        
        
          
        Tick the filters whose torrents nzb2seed should build. Ticking adds a watch-folder action called "nzb2seed" to the filter and enables the filter in autobrr; unticking removes that action and disables the filter in autobrr, so nothing acts on its releases until you enable it there again. The filter's other actions (qBittorrent, SABnzbd…) are not removed.
        
          
        
          A ticked filter is enabled in autobrr and its releases come to nzb2seed. Unticking puts that filter and its actions back exactly as they were.
          
        
            
            
          
        
        
        
      
        
      
        
        
        Inbox and behaviour

        What your seeding returns
        
    
        Measured from your own torrents in qBittorrent - nothing is sent anywhere. The number is upload per GB stored: 1.00 means a torrent has given back as much as it takes up. Only torrents older than the settling time count, because a new one has not had its chance yet.

        Only build what pays for its space
        
        
        Automatic builds can be weighed before they start, against what your own torrents have actually returned. The rules themselves live on the Demand tab, where each one is shown with the evidence behind it; these two settings decide how much evidence a rule needs.
        
        
        
          
          
        
        
      
        

      
        
        
        Free space
        
        
        Off unless you set a limit. When the disk builds are written to falls below it, SABnzbd's queue is paused, no new automatic build is started, and a build already running stops before its next big write instead of filling the disk - until there is room again - freed by the sweep below, or by you. Only what nzb2seed paused is started again, and seeding is never touched.
        
        
        
          
          
        
        
        
        
        
          
        
      
        

      
        
        
        Removing builds again
        
        
        Off unless you switch it on. When it is on, a torrent nzb2seed built is removed from qBittorrent once it is older than the age below, and the files nzb2seed placed for it are deleted. Only files nzb2seed put there go - it deletes from the record each build writes, so anything you added yourself, a metadata folder, or another torrent's data in the same place is left alone. Seeding stops when the torrent is removed, so set an age your trackers are happy with.
